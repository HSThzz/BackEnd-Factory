# Architecture Guide

## Overview

All projects generated by `create-backend-api` follow **DDD (Domain-Driven Design)** and **Clean Architecture** principles. This ensures:

- **Separation of Concerns**: Each layer has a specific responsibility
- **Testability**: Each layer can be tested independently
- **Maintainability**: Clear boundaries between business logic and infrastructure
- **Scalability**: Easy to extend and modify

## Architecture Layers

### 1. Domain Layer

**Location**: `src/domain/`

The domain layer contains the core business logic and is independent of external frameworks.

#### Structure

```
domain/
├── entities/        # Domain entities (business objects)
└── repositories/    # Repository interfaces (contracts)
```

#### Key Components

- **Entities**: Core business objects with business logic
- **Repository Interfaces**: Contracts defining data access operations
- **Value Objects**: Immutable objects representing domain concepts

**Example Entity** (TypeORM):

```typescript
import { Entity, Column } from 'typeorm';
import { BaseEntity } from './BaseEntity';

@Entity('users')
export class User extends BaseEntity {
  @Column()
  email: string;

  @Column()
  name: string;
}
```

### 2. Application Layer

**Location**: `src/application/`

The application layer contains use cases and application services that orchestrate domain objects.

#### Structure

```
application/
├── use-cases/    # Business use cases
├── services/     # Application services
└── dtos/         # Data Transfer Objects
```

#### Key Components

- **Use Cases**: Single-purpose business operations
- **Services**: Application-level services
- **DTOs**: Data structures for transferring data between layers

**Example Use Case**:

```typescript
export class CreateUserUseCase {
  private repository: IUserRepository;

  constructor() {
    this.repository = new UserRepository();
  }

  async execute(data: CreateUserDTO): Promise<User> {
    // Business logic here
    return this.repository.create(data);
  }
}
```

### 3. Infrastructure Layer

**Location**: `src/infrastructure/`

The infrastructure layer contains implementations of interfaces defined in the domain layer.

#### Structure

```
infrastructure/
├── database/
│   ├── repositories/  # Repository implementations
│   └── migrations/    # Database migrations
└── config/           # Configuration files
```

#### Key Components

- **Repository Implementations**: Concrete implementations of domain repositories
- **Database Configuration**: Database connection and setup
- **External Services**: Third-party service integrations

**Example Repository** (TypeORM):

```typescript
export class UserRepository
  extends BaseRepository<User>
  implements IUserRepository
{
  constructor() {
    super(User);
  }
}
```

### 4. Presentation Layer

**Location**: `src/presentation/`

The presentation layer handles HTTP requests and responses.

#### Structure

```
presentation/
├── controllers/  # Request handlers
├── routes/       # Route definitions
└── middleware/   # Express/Fastify middleware
```

#### Key Components

- **Controllers**: Handle HTTP requests and delegate to use cases
- **Routes**: Define API endpoints
- **Middleware**: Request processing (validation, authentication, etc.)

**Example Controller**:

```typescript
export class UserController extends BaseController {
  private useCase: CreateUserUseCase;

  async create(req: Request, res: Response): Promise<Response> {
    const data: CreateUserDTO = req.body;
    const user = await this.useCase.execute(data);
    return this.created(res, user);
  }
}
```

## Dependency Flow

```
Presentation → Application → Domain
     ↓              ↓
Infrastructure ←────┘
```

**Rules:**
- Outer layers can depend on inner layers
- Inner layers **never** depend on outer layers
- Domain layer has **no dependencies** on other layers

## Benefits

### 1. Testability

Each layer can be tested in isolation:

```typescript
// Test use case without database
const mockRepository = new MockUserRepository();
const useCase = new CreateUserUseCase(mockRepository);
```

### 2. Flexibility

Easy to swap implementations:

```typescript
// Switch from TypeORM to Prisma
// Only infrastructure layer changes
```

### 3. Maintainability

Clear separation makes code easier to understand and modify.

### 4. Scalability

Add new features by extending existing layers without breaking existing code.

## Adding New Features

### Step-by-Step Guide

1. **Create Domain Entity** (`src/domain/entities/`)
   ```typescript
   export class Product extends BaseEntity {
     // Properties
   }
   ```

2. **Define Repository Interface** (`src/domain/repositories/`)
   ```typescript
   export interface IProductRepository extends IBaseRepository<Product> {
     // Custom methods
   }
   ```

3. **Implement Repository** (`src/infrastructure/database/repositories/`)
   ```typescript
   export class ProductRepository extends BaseRepository<Product> {
     // Implementation
   }
   ```

4. **Create DTOs** (`src/application/dtos/`)
   ```typescript
   export interface CreateProductDTO {
     // Fields
   }
   ```

5. **Implement Use Case** (`src/application/use-cases/`)
   ```typescript
   export class CreateProductUseCase {
     // Business logic
   }
   ```

6. **Create Controller** (`src/presentation/controllers/`)
   ```typescript
   export class ProductController extends BaseController {
     // HTTP handlers
   }
   ```

7. **Add Routes** (`src/presentation/routes/`)
   ```typescript
   router.post('/products', (req, res) => 
     productController.create(req, res)
   );
   ```

## Best Practices

1. **Keep Domain Pure**: No framework dependencies in domain layer
2. **Use Interfaces**: Depend on abstractions, not concretions
3. **Single Responsibility**: Each class/function has one job
4. **Dependency Injection**: Inject dependencies through constructors
5. **Error Handling**: Handle errors at appropriate layers
